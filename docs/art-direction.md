# 网上柳州 · M01 美术与界面规范（定稿 v1）

> 配套文档：`docs/architecture.md`（坐标、数据、性能预算以该文为准）。
> 适用范围：M01 五星街周边 500 m × 500 m 白模。

---

## 1. 风格定位

**数据沙盘白模**：画面像一张可旋转的三维地图，不是写实城市。

- 每个体块都来自 OSM 要素。画面要让观众一眼分辨「有数据」「按层数估算」「缺失」三种状态。
- 不加贴图、招牌、广告、树木散布、车流、人群等装饰。这些内容在 OSM 中未核实，加上去就是虚构。
- 延续现有 UI 的深青灰底色与青绿强调色（`src/style.css`），3D 场景与 HUD 统一色调。

禁止项：

1. 随机或程序化填充建筑。
2. 虚构地标、店名、门牌、路名标注（路名只在 OSM `name` 标签存在时显示）。
3. 真实人物的肖像或可识别形象。
4. 品牌商标与第三方地图的视觉元素或底图截图。

## 3. 材质与光照

### 3.1 材质

- 全部使用 `MeshStandardMaterial`，`metalness = 0`。建筑 `roughness = 0.85`，道路 `0.95`，水体 `0.35`。
- 每种「kind × 状态」一个共享材质实例，配合按瓦片合并，控制 draw call。
- 斜纹用 shader 在世界坐标中计算（`onBeforeCompile` 注入），不用贴图，避免 UV 生成与拉伸变形。
- 道路与地面之间用层高（`architecture.md` 第 5.2 节）加 `polygonOffset` 防止闪烁。

### 3.2 默认光照「午后」

数值固定，保证截图对比可复现。不模拟真实太阳位置与时间。

| 项 | 值 |
|---|---|
| 色调映射 | `ACESFilmicToneMapping`，曝光 1.0；输出 `SRGBColorSpace` |
| 半球光 | 天空 `#BCD2E0`，地面 `#293744`，强度 1.6 |
| 平行光（太阳） | `#FFE0B5`，强度 2.4；方向从西南上方照来：方位角 225°（自北顺时针），高度角 50° |
| 阴影 | 仅平行光投射，`PCFSoftShadowMap`，2048²；正交阴影相机覆盖 `[−300, 300]²`，`bias = −0.0005`，`normalBias = 0.5` |
| 投射阴影 | 建筑；道路与地面只接收 |
| 雾 | `Fog(#101820, 600, 1400)` |

太阳方向换算到本地坐标：方位角 225° 指西南，光从该方向射向原点，光源位置 `(−sin45°·cos50°, sin50°, +cos45°·cos50°) × 400` ≈ `(−182, 306, 182)`（X 东为正，Z 南为正）。

### 3.3 备选光照「阴天检视」（按 `H` 高亮缺失时也可用）

半球光强度 2.4，平行光 0.6，关闭阴影。用于数据检查：阴影不遮挡建筑状态色。

## 4. 缺失数据视觉规范

| 场景 | 表现 |
|---|---|
| 缺失高度建筑 | 3 m 占位体块 + 斜纹 + 顶面洋红描边（第 2.2 节） |
| 按 `H` 高亮 | 其他建筑降到 30% 不透明度，缺失建筑保持原样 |
| HUD 计数 | `缺失高度 N / 总数 M 栋`，N > 0 时文字用警告色 |
| 无法组装的要素 | HUD 一行：`未能组装 K 个要素（详见 manifest）` |
| 裁剪区外 | 暗色地面，无体块，无提示文字 |
| 数据加载失败 | 全屏中央提示「数据加载失败：<原因>」，不回退到演示白模 |

文案统一用「缺失」「估算」「来自 OSM」，不用「暂无」「约」「真实」等含糊或夸大的词。

## 5. 界面布局

```
┌ header: LZ.OL ·············································· PRE-ALPHA 0.x ┐
│                                                                          │
│ panel（左上）                                           指北针（右上）   │
│  LIUZHOU ONLINE                                          ▲ N             │
│  网上柳州                                                                │
│  数据说明一句话                                                          │
│                                                                          │
│                            3D 视口                                       │
│                                                                          │
│ 图例（左下，L 切换）                  信息卡（点击要素后出现，右侧）      │
│                                                                          │
│ © OpenStreetMap contributors（左下最底）    HUD（右下）: FPS · 统计       │
└──────────────────────────────────────────────────────────────────────────┘
```

### 5.1 组件

- **面板文案**：接入真实数据后改为「五星街周边 500 m 范围，建筑与道路来自 OpenStreetMap。灰紫斜纹为缺失高度的建筑。」不得出现「真实还原」「1:1」等说法。
- **指北针**：直径 48 px，指针始终指向世界 −Z 在屏幕上的方向；点击等同按 `N`。
- **图例**：三种建筑状态色块 + 道路分类色块，每项一行；12 px 文字。
- **信息卡**：宽 280 px，字段依次为：类型（建筑 / 道路）、名称（仅 `name` 标签存在时）、OSM ID（链接 `https://www.openstreetmap.org/<type>/<id>`，新标签页打开）、高度及来源、宽度及来源、所在瓦片。
- **HUD**：`WebGL 正常 · 60 FPS · 调用 87 · 三角形 312k · 缺失高度 N/M`。
- **署名**：常驻、不可关闭、对比度不低于 4.5:1，链接到 `https://www.openstreetmap.org/copyright`。

### 5.2 字体与尺寸

- 字体沿用 `'Segoe UI', 'Microsoft YaHei UI', sans-serif`。
- 字号：标题 46 px（移动端 35 px），正文 13 px，HUD / 图例 12 px，眉题 11 px 字距 0.26em。
- 交互元素最小点击区域 32 × 32 px。
- 宽度 ≤ 650 px 时，信息卡改为底部抽屉，图例默认收起。

### 5.3 路名标注（可选）

- 仅对 `road.major`、`road.minor`、`road.pedestrian` 且带 `name` 标签的道路显示。
- 使用 CSS2D 或 Sprite，沿最长段中点放置，相机距离 > 400 m 时隐藏。
- 字色 `#AFC4CB`，描边 `#101820`。

## 6. 比例参照物（M01 可选）

只用于判断尺度，不代表真实人、车或交通状况。

| 物体 | 形状 | 尺寸 | 颜色 |
|---|---|---|---|
| 人 | 胶囊 | 半径 0.3 m，高 1.7 m | `#8AD2C8` |
| 电动自行车 | 盒体 | 长 1.8、宽 0.7、高 1.1 m | `#86B9B8` |
| 小汽车 | 盒体 | 长 4.5、宽 1.8、高 1.5 m | `#86B9B8` |

放置在原点附近一处，旁边 CSS2D 标签「比例参照」。M01 之后的角色与车辆模型沿用这些尺寸，风格为低多边形、无面部特征、纯色材质。

## 7. GLB 地标资产规范

| 项 | 要求 |
|---|---|
| 格式 | glTF 2.0 `.glb`，单位米，+Y 向上 |
| 原点 | OSM 轮廓质心的地面处 |
| 面数 | 单个地标 ≤ 20 000 三角形；M01 全部地标合计 ≤ 100 000 |
| 贴图 | 每个地标最多 1 张 1024² 基础色 + 1 张 1024² ORM；或无贴图纯色 |
| 材质 | PBR metallic-roughness；色调须落在第 2.2 节 `osm.height` 色带附近，不得比周边白模明显写实 |
| 命名 | `way-<id>.glb` / `relation-<id>.glb`，与 OSM ID 一一对应 |
| 元数据 | 必须在 `landmarks/manifest.json` 登记作者、许可、来源、建模依据（`architecture.md` 第 8.1 节） |
| 轮廓吻合 | 模型底面投影与 OSM 轮廓的偏差 ≤ 1 m；偏差更大时先修 OSM 轮廓或在 manifest 中说明 |
| 禁止 | 来源不明的下载模型、从地图应用或游戏中提取的模型、含可识别商标的贴图 |
